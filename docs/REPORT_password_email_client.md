# דו"ח לקוח: ממשק משתמש להגדרה ואיפוס סיסמה במייל (REPORT_password_email_client.md)

## מה נבנה (What Was Built)
ממשקי המשתמש (Client) לתהליכי איפוס סיסמה, הגדרת סיסמה ראשונית ושליחת הזמנות:
1. **דף בקשת איפוס סיסמה (`/forgot-password`)**:
   - טופס הזנת אימייל עם הגנה מובנית מפני דליפת מידע.
   - מענה אחיד וניטרלי ("אם הכתובת קיימת במערכת, נשלח אליה קישור לאיפוס סיסמה").
   - נטרול כפתור השליחה בזמן ביצוע הבקשה למניעת שליחה כפולה.
2. **דף הגדרת/איפוס סיסמה (`/reset-password`)**:
   - קריאת הטוקן מה-URL ומחיקתו המיידית משורת הכתובת (`window.history.replaceState`) למניעת הדלפה בהיסטוריה או ב-Referrer.
   - בדיקת תקינות הטוקן מיד עם טעינת הדף מול השרת.
   - מצבי ממשק: טעינה, שגיאה/פג תוקף (עם קישור חזרה לבקשת איפוס), וטופס פעיל.
   - התאמת כותרת וניסוח לפי מטרת הטוקן (`invite` -> "הגדרת סיסמה ראשונית", `reset` -> "איפוס סיסמה").
   - שדות סיסמה חדשה + אימות סיסמה, בדיקת כללי סיסמה חיים (8-72 תווים, אות וספרה) ומד חוזק סיסמה ויזואלי.
   - הצלחה: הצגת Toast ניווט אוטומטי לדף ההתחברות (`/login`).
3. **דף התחברות (`/login`)**:
   - הוספת קישור "שכחת סיסמה?" המפנה ל-`/forgot-password`.
4. **דף ניהול משתמשים (`/admin/users`)**:
   - בטופס יצירת משתמש חדש: הסיסמה הפכה לאופציונלית עם תיבת סימון "שלח הזמנה במייל להגדרת סיסמה" (מסומנת כברירת מחדל). בעת סימונה, שדה הסיסמה מוסתר ומושמט מה-payload הנשלח.
   - לאחר יצירת המשתמש: הצגת חיווי האם שליחת ההזמנה הצליחה (`inviteSent`).
   - בטבלת המשתמשים: תגית "ממתין להגדרה" וכפתור פעולה "שלח הזמנה מחדש" עבור משתמשים שטרם הגדירו סיסמה (`passwordSet === false`).
5. **דף פרופיל אישי (`/profile` או `/shared/profile`)**:
   - הנחיות ולידציה מובנות לפי מדיניות הסיסמאות המשותפת בעת שינוי סיסמה.

## קבצים שנוצרו / שונו / נמחקו (Files Modified / Created / Deleted)

## החלטות עיצוב ואבטחה (Design & Security Decisions)
- **מניעת זליגת טוקן**: הטוקן נקרא מפרמטר ה-URL ומייד מנוקה בעזרת `replaceState`. הטוקן לא נשמר ב-localStorage או ב-sessionStorage בשום שלב.
- **נגישות (Accessibility)**: כל שדות הקלט מצוידים ב-labels, זיהוי שגיאות עם `role="alert"` ו-`aria-live` עבור הודעות סטטוס.
- **RTL ועקביות עיצובית**: שימוש ברכיבי ה-UI הקיימים (`Card`, `Input`, `Button`, `Badge`, `Spinner`, `Toast`) תוך שמירה על RTL טבעי ומשתני CSS מערכתיים.
